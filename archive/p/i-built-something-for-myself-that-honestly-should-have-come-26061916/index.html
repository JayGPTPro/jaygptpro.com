I built something for myself that honestly should have come built into Claude Code

A few months ago, I built a small coaching layer inside my Claude Code setup.

Only later did I realize how useful it actually was.

I got so used to it,
I forgot it doesn’t come built in for everyone.

Basically, I turned Claude Code into a kind of personal coach.

Not just a tool that does the work for me,
but something that occasionally notices how I’m working and drops a smart note at exactly the right moment.

It always marks those notes with a 💡, so whenever I see it, I know this is an insight worth stopping for.

For example:
💡 This conversation is getting long. It might be a good time to use /compact.
💡 This process repeats with every new product. Worth turning it into a Skill.
💡 This pricing decision is worth documenting, so I don’t restart the same discussion a month from now.
💡 This is already the third time you’re handling the same customer question. Maybe it’s worth fixing on the product page.

It does not stop the work.

It still does exactly what I asked it to do,
but at the same time, it coaches me on how to work with it better.

Lately, I keep catching myself reading those 💡 notes and thinking:

Yep.
That’s true.
Good thing it reminded me.

Because when you work a lot with Claude Code,
the challenge is not just getting it to complete tasks.

The real challenge is building a smarter workflow around all the things that keep repeating in the business.

And this small layer helps a lot with that.

You install it once in your global CLAUDE.md,
and from that moment on, it loads automatically in every project and helps you become a better Claude Code user while you work.
